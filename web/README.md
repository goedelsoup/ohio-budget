# web

Web interface layer for this repository. Optional — add only when direct programmatic
access to the domain computer is insufficient for the intended use.

See [web conventions](../.yidam/.vendor/prelude/guidelines/directories.md#web) for what
belongs here.

Not applicable at genesis. The corpus is small enough to read directly and has no audience
beyond its contributors yet.

What would trigger adding it: this domain has an unusually strong public-interest case for
a browsable interface, because the questions people actually bring to a state budget —
*what happened to funding for this program*, *what does my school district receive*, *what
changed between the governor's proposal and the enacted bill* — are traversals of the graph
rather than searches over it. A web layer earns its place once the corpus carries enough
line item lineage to answer the first of those questions across more than one biennium.

When that point arrives, the primary data source should be a bundled export feed with a
contract version (`yidam bundle`), not the corpus directly, so the interface is decoupled
from corpus restructuring.
