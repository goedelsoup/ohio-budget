# ohio-budget

This repository tracks the Ohio state budget as a connected system — revenue instruments,
statutory funds, appropriation line items, the legislative and executive actions that move
them, and the state agencies and local jurisdictions the money reaches. It covers the full
appropriation surface across fiscal years 2010 to the present.

The central question is where the gap lies between what Ohio appropriates and what Ohio
actually spends, and what the record shows about how that gap arises.

## Read this first

No dollar figure in this corpus is asserted without a committed source behind it. A figure
either carries `[verified]` and cites a catalogued document, or it carries `[open]` and says
what is missing. Nothing is remembered.

That rule is the whole design. A corpus that states precise, unsourced dollar figures at line
item granularity is worse than one that states none: the figures are citable, they look
authoritative, and nothing downstream can detect that they were remembered rather than read.

Extraction has since run across several biennia, so the catalog is populated and most figures
carry `[verified]`. The `[open]` tags that remain are the honest inventory of what no committed
source yet answers — they are load-bearing, not leftovers.

Counts belong below rather than here. A number written into prose is the one thing in this
repository that reliably goes stale, and this section was itself the longest-standing example
of it — see [claims-about-repository-state](.yidam/decisions/claims-about-repository-state.yml).

## Working in this repository

```
mise run yidam-build   # once, per clone — the gate calls the `yidam` binary by name
mise run ci            # the full gate
```

Run the gate before opening a pull request. [`.github/workflows/ci.yml`](.github/workflows/ci.yml)
installs the toolchain and then runs `mise run ci` — the same command, from the same definition in
[`mise.toml`](mise.toml) — so the workflow reports nothing that was not already visible locally.
Adding a check means editing `[tasks.ci]` and nothing in the workflow. Agents working here are
given the same instruction in [CLAUDE.md](CLAUDE.md).

There is no commit-time hook. `mise run ci` compiles the workspace, runs every test, and builds the
site, which is the right cost once per pull request and the wrong cost per commit; and a hook lives
in `.git/hooks`, which is not tracked, so it only ever ran in the clones where someone had
remembered to install it.

While writing, `mise run validate` is the fast subset worth running by hand. It checks the corpus
rules alone — no compile, no tests — and catches the failure this repository keeps having: a node
asserting something about the repository that stopped being true, a source described as
uncatalogued after it was catalogued, an amount described as unfilled after it was filled. Both
halves of such a contradiction look correct in isolation, and the stale half is usually written in
the same commit that falsifies it. See
[claims-about-repository-state](.yidam/decisions/claims-about-repository-state.yml).
